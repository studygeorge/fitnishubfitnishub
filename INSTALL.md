# Инструкция по установке FitnesHub на сервер

## Шаг 1: Создание скриптов на сервере

Выполните эти команды на вашем сервере (root@ruvds-f2wwn):

```bash
# Создание директорий для скриптов и бекапов
mkdir -p /home/fitneshub/scripts
mkdir -p /home/fitneshub/backups/db
mkdir -p /home/fitneshub/backups/code

# Создание директорий для логов
mkdir -p /home/fitneshub/backend/logs
```

## Шаг 2: Копирование скриптов

Скопируйте файлы из `/home/fitneshub/scripts/` в вашу локальную директорию на сервере.

Все скрипты уже находятся в Git-репозитории, поэтому после pull они будут доступны.

## Шаг 3: Установка прав на выполнение

```bash
chmod +x /home/fitneshub/scripts/*.sh
```

## Шаг 4: Настройка алиасов

```bash
# Добавление алиасов в .bashrc
cat /home/fitneshub/scripts/bash-aliases.sh >> ~/.bashrc

# Применение изменений
source ~/.bashrc

# Проверка установки
fh-help
```

## Шаг 5: Первый деплой

```bash
# Выполните первый деплой вручную, чтобы убедиться что все работает:
bash /home/fitneshub/scripts/deploy.sh development
```

## Шаг 6: Проверка работоспособности

```bash
# Проверка статуса
fh-status

# Проверка логов
fh-logs

# Проверка API
fh-health
```

## Готово!

Теперь вы можете использовать одну команду для деплоя:

```bash
fh-deploy
```

## Важные замечания:

1. **Бекапы создаются автоматически** перед каждым деплоем
2. **База данных НИКОГДА не удаляется** - только создаются бекапы
3. **Хранится 10 последних бекапов БД** - старые автоматически удаляются
4. **Откат выполняется командой** `fh-rollback`
5. **Все команды доступны через алиасы** `fh-*`

## Workflow:

1. Разработка локально или в ветке development
2. Коммит и push в GitHub
3. На сервере: `fh-deploy` (одна команда!)
4. Проверка: `fh-status` и `fh-health`
5. Если что-то пошло не так: `fh-rollback`
